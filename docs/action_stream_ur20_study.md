# 面向 UR20 螺钉拆卸具身 Agent 的阶段守卫动作流融合研究

## 摘要

视觉语言模型控制的具身 Agent 通常在每个短动作后重新调用策略模型，长任务因而承担较高的推理等待开销。本文将 HexaShell 代码库实验性 P3b 动作流提交中的闭合性、前置条件与效果冲突原则，适配到 UR20 电池螺钉拆卸仿真：在自由空间中将最多四个绝对笛卡尔路点作为一个策略动作提交，并在每个路点前后检查轴向接触、视觉置信度和横向对齐阶段；任一守卫触发即结束当前动作段并交回最新观测。该方法保留 UR20 原有的单步运动限幅、视觉门控、力觉接触门控、顺应接近、螺旋搜索、触觉就座确认与旋出控制。我们使用两条已归档的 `state_id=0` 决策轨迹进行配对确定性重放。策略轮次从 56 降至 26（减少 53.6%）；按归档模型响应延迟计算的投影总时长从 1926.0 s 降至 1087.7 s（减少 43.5%）。实际仿真重放时间为 528.8 s 和 525.8 s，动作数与物理步数相同。native 与 fused 均在 2 条来源轨迹中成功 1 条；成功回合的相对旋出位移为 21.011 mm，episode 峰值抬升为 20.985 mm。两条来源轨迹来自同一初始状态且回放固定策略决策；结果仅描述该配对回放，不能证明总体成功率非劣，也不能代表在线模型的端到端时延。

**关键词：** 具身 Agent；UR20；螺钉拆卸；动作流；阶段守卫；MuJoCo

## 1 引言

具身 Agent 需要在高层语义推理与低层连续控制之间协调。若每个短路径片段都等待一次视觉语言模型响应，模型服务延迟会累积在任务的关键路径上。另一方面，机械臂的接近、接触和工具操作并非可互换阶段：在自由空间合并动作有机会减少模型往返，而在视觉不确定或接触后继续沿用过期决策可能破坏精确对准或接合。

本文研究的 UR20 任务要求机械臂将六角套筒对准 M6 螺钉，确认套接后通过旋转完成螺钉提取。控制器已有独立的视觉估计、力觉顺应和触觉搜索机制。本文的目标是在不改变这些任务阶段控制原语的前提下，减少自由空间接近中相邻策略动作的调用次数。本文贡献是：

1. 将 HexaShell 的流式提交和效果守卫思想映射为 UR20 的有界路点序列工具；
2. 将接触、视觉置信度及 XY 对齐状态转换封装为机器人适配器公开的提交条件；
3. 提供成对历史决策重放、逐步轨迹与力迹记录，并报告该小样本实验能够支持的结论边界。

## 2 相关工作与任务系统

### 2.1 HexaShell 执行框架与动作流提交

HexaShell 以通用机器人 API、Python 单元运行时、感知与运动适配器及可选任务技能构成跨基准 harness [1]。其论文并未提出本文采用的动作流提交方法。该原则来自本地代码库的实验性 P3b 方法原型 [4]：`hexashell/method/stream_commit.py` 将闭合语句、已知前置条件和后续效果不冲突作为提前提交条件；`hexashell/runtime/action_stream.py` 则对流式到达的单元做单语句前视，条件不足时交回常规执行路径。P3b 同时包含观测充分集、精度分配、提交点规划、批量取回、不变量和分支预生成等原型，但本文只借鉴动作流提交原则，不移植其事实 IR、精度调度或分支生成器。

UR20 控制接口与 HexaShell 的 Python 单元接口不同：它以单次函数调用返回一个动作，没有增量代码流或任务事实 IR。因此本文不移植其语法解析器，也不对分支作推测生成；我们把闭合性、前置条件和效果边界映射为有限长度的路点动作序列与环境状态守卫。该序列只作用于连续自由空间 `move_to` 路点，不跨越接触搜索、套筒接合或旋出阶段。

### 2.2 UR20 任务与控制流程

任务环境由 MuJoCo 场景 [2]、仿真 worker、机器人适配器、视觉估计、策略客户端和动作映射组成 [3]。策略只能读取 `agentview` 与 `wristview` 图像及公开状态；接合、螺钉转角和抬升量由环境内部用于评测。任务流程为：粗定位、视觉 XY 对准、轴向接近、力觉确认接触、顺应螺旋搜索、触觉与视觉复核套接、旋转提取。

相关现有参数为：动作幅度放大系数 3.0（范围 1–5）、笛卡尔策略目标单步最大位移 0.05 m、视觉横向运动置信度门槛 0.7、XY 锁定进入阈值 2 mm 与释放阈值 3 mm、轴向接触力阈值 1 N。螺旋搜索和旋出分别由专用阻塞式控制原语执行，不纳入路点合并。

## 3 阶段守卫动作流

### 3.1 动作表示

新增 `move_sequence` 工具接收 1–4 个绝对世界坐标目标。每个目标仅允许给出 `x`、`y`、`z` 的非空子集；未给出的轴沿用当前观测位置。每个路点都经已有的 `action_for("move_to", ...)` 映射并单独调用 `robot.step`，因此融合只减少策略轮次，不合并物理控制步，也不绕过既有单步限幅。

### 3.2 提交守卫

适配器在动作段开始时记录 XY 对齐锁定状态。每个路点执行前后都检查以下条件：

\[
G_t = C_t \lor (\gamma_t < 0.7) \lor (A_t \ne A_0),
\]

其中 \(C_t\) 表示检测到轴向接触，\(\gamma_t\) 是视觉估计置信度，\(A_t\) 是当前 XY 对齐锁定状态，\(A_0\) 是段开始时的状态。若 \(G_t\) 为真，动作段立即结束并把最新观测交回策略。段开始前也检查该条件，避免在已接触、视觉不可靠或对齐阶段已变化时启动自由空间序列。

此守卫对应动作流式提交中的“前置与效果边界”：自由空间策略假设只在状态未跨越控制阶段时继续有效；接触、视觉置信度下降或对齐锁定切换均构成重新决策点。所有点仍由 UR20 适配器的视觉/力觉约束执行，阶段守卫不代替这些低层约束。

### 3.3 失败与终止处理

路点参数在任何仿真步推进前完成验证。执行中若出现参数或适配器故障，工具结果记录已执行路点数和错误，随后以当前观测恢复策略交互。任务成功和环境终止条件在每个路点之后检查。`move_sequence` 是显式启用的可选工具；默认 native 模式仍只暴露逐次 `move_to`。

## 4 实验设计

### 4.1 数据与配对协议

实验读取仓库 `archive/rollouts/` 中两条完整历史轨迹：`20261109_183017_agentview_primary` 与 `20261109_191326_wristview_primary`。二者的原始摘要均记录成功，均对应 `state_id=0`，但使用不同的视觉配置和历史运行条件。对每条来源轨迹分别执行 native 与 fused 重放：native 按原顺序逐个执行工具调用；fused 将相邻且最多四个的 `move_to` 调用合为一个策略轮次，并遵守阶段守卫。两种模式均使用当前仿真代码、同一初始状态、最大 7500 环境步、力反馈、顺应控制、螺旋搜索、套筒旋出和动作放大系数 3.0。

回放不调用在线语言模型。策略轮次是由记录中的相邻 `move_to` 分组后得到；执行墙钟时间包括仿真重放。另报告“投影总时长”，其定义为仿真重放时间加上已归档 API 响应延迟之和。融合模式只把每个合并组首个历史调用的延迟计入投影，因此该值是固定历史延迟假设下的反事实估算，不是融合策略在线运行的实测端到端时延。

### 4.2 指标与成功判据

主要指标为策略轮次数、机器人动作数、环境步数、物理步数、仿真重放墙钟时间及任务成功。旋出成功要求相对旋出起点的关节实测轴向位移达到 21 mm，且回合中观察到有效几何接合；最大抬升量与旋出完成标志分别保留。接触搜索和工具旋出仍由原有阻塞控制原语执行，只有其后的任务成功结果受实测位移阈值约束。

### 4.3 复现

安装项目依赖后，在仓库根目录运行以下命令；输出目录必须不存在：

```bash
MUJOCO_GL=egl PYTHONPATH=src python scripts/evaluation/replay_action_stream.py \
  --output outputs/fusion_replay_lift21_run1 \
  --traces archive/rollouts/20261109_183017_agentview_primary/summary.json \
           archive/rollouts/20261109_191326_wristview_primary/summary.json
```

完整指标写入 `results.json`；每个回合目录保留工具尖端轨迹与螺旋力迹。本文配对记录位于 `outputs/fusion_replay_verified21_20261123/`。本文没有发起在线模型调用，归档 API 响应延迟仅用于同历史延迟假设下的投影。在线对照需在相同模型、初始状态、预算和控制参数下运行两个策略模式，并独立记录融合输出的实际生成延迟。

## 6 讨论

动作流融合的直接收益来自减少模型调用边界，不是机器人轨迹或 MuJoCo 物理步数的减少。本实验的机器人动作数和物理步数完全相同，重放墙钟时间差异为 0.6%；因此可直接确认的是调用轮次压缩，投影总时长下降依赖归档 API 延迟假设。真实端到端时延还取决于融合后模型生成时长、工具参数长度、网络排队及在线模型是否生成相同动作序列，当前实验没有测量这些因素。

重放还能检验跨控制阶段继续执行的风险。若历史轨迹在当前版本中进入接触、搜索或视觉不确定阶段，阶段守卫会结束合并段；但固定决策重放仍无法模拟模型看到序列结果后采取的新动作。因此，配对结果适用于比较控制调用压缩和轨迹重放，不等价于完整在线闭环的成功率对照。

## 7 局限

1. 只有两条历史轨迹，且两者均为同一 `state_id`，不具备独立初始状态覆盖，也无法估计成功率差异的置信区间。
2. 回放固定历史策略决策；它不测量融合工具对在线模型行为、输出延迟或任务恢复能力的影响。
3. agentview 来源轨迹在两种重放模式下均未建立接合；wristview 来源轨迹则在两种模式下都达到旋出阈值。该差异属于两条固定策略轨迹的表现，不能解释为视觉配置或动作融合的因果效应。
4. MuJoCo 使用理想螺旋副，未覆盖真实螺纹摩擦、材料形变和实机控制延迟；当前结果不证明真实 UR20 上的安全性或有效性。
5. 环境成功判定依据相对旋出起点的实测关节位移和有效接合；episode 峰值抬升量从场景零位统计，因此会略低于相对位移。结果文件同时保留两个量以便核查。

## 8 结论

本文将具身 Agent 的动作流提交思想实现为 UR20 自由空间有界路点序列，并用接触、视觉置信度和 XY 对齐状态变化作为显式提交边界。方法保持原有低层逐点控制和任务专用接触原语。在两条同状态历史轨迹的确定性重放中，策略轮次减少 53.6%，投影总时长减少 43.5%，而实际仿真重放时间基本持平；任务结果为 native 和 fused 各成功 1/2。该结果支持动作调用压缩可与本任务控制阶段守卫结合，但尚不足以证明在线速度提升或总体成功率非劣；后续需在多个独立初始状态上进行重复的在线配对实验。
